## Overview

Colours are semantic: tokens describe purpose, not appearance. Every colour adapts automatically between light and dark through CSS `light-dark()`, so your code never references raw hex colours, and switching the colour scheme (or nesting a dark island) needs no code at all.

The values are Tecton's. Role values in both modes come from the Tecton design-system export, which has a designed light mode and a designed dark mode. Where the export has no role for a semantic token, the owner's Tecton theme bindings supply it, and a small number of roles are rebound where the export's value would fail contrast (recorded on the [All tokens](../tokens/) page and in the token build). The palette is graphite, mauve, violet and lilac neutrals with a hot-pink focus ring; status colours are green, red and yellow, plus a blue info ladder.

[All tokens](../tokens/#colour-tokens) lists every colour token with its light and dark value.

## Surface colors

The surface hierarchy is body, surface, card and popover. Each level sits visually above the previous one.

| Token                          | Light      | Dark       | Use                                                                 |
| ------------------------------ | ---------- | ---------- | ------------------------------------------------------------------- |
| `--color-background-body`      | `#f6f4f7`  | `#1d1c1f`  | The page                                                            |
| `--color-background-surface`   | `#fafafb`  | `#131214`  | Panels, sections, regions                                           |
| `--color-background-card`      | `#fafafb`  | `#131214`  | Cards                                                               |
| `--color-background-popover`   | `#fafafb`  | `#131214`  | Menus, popovers, dialogs                                            |
| `--color-background-muted`     | `#f0eef3`  | `#28232c`  | Code and keyboard backgrounds, table stripes, recessed areas        |
| `--color-background-inverted`  | `#21172a`  | `#f6f5f8`  | Tooltips and other inverted surfaces (the primary ink colour)       |

Tecton's depth model is flat. In dark mode, elevation runs _darker_: a panel is darker than the page (`#131214` on `#1d1c1f`), not lighter. In light mode the panel is a touch lighter than the page. Surface, card and popover share one value in both modes, so their separation comes from a one-pixel border (`--color-border`) rather than a shade. See [Elevation](../elevation/).

## Text, icons and borders

| Role      | Tokens                                                                                                                        |
| --------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Text      | `--color-text-primary`, `--color-text-secondary`, `--color-text-disabled`, `--color-text-accent`, plus the fixed `--color-on-dark` and `--color-on-light` |
| Icons     | `--color-icon-primary`, `--color-icon-secondary`, `--color-icon-disabled`, `--color-icon-accent`                              |
| Borders   | `--color-border` (a subtle rule, the default), `--color-border-emphasized`                                                    |
| Overlays  | `--color-overlay` (a 50 % black scrim), `--color-overlay-hover` and `--color-overlay-pressed` (5 % and 10 % ink washes)       |
| Effects   | `--color-skeleton`, `--color-track`, `--color-shadow`, `--color-tint-hover`                                                   |

Two rules keep text and borders honest:

- **Content uses two text colours, primary and secondary, and nothing dimmer.** `--color-text-disabled` is for disabled controls: it does not reach 4.5:1 by design.
- **`--color-border-emphasized` is 2.2:1 on the page in both modes** (it is Tecton's "divider medium"). Use it for decorative separation. If a border is the only thing that shows where a control begins or what state it is in, use a border that measures at least 3:1, such as `--tecton-color-divider-strong` (3.1:1). See [Accessibility](../accessibility/#known-contrast-shortfalls).

## Accent: fill and ink

`--color-accent` (a mauve `#644a78` in light mode, `#5d4d68` in dark) is a **fill**: the primary action background. As ink it works in light mode (6.9:1) but not in dark (2.2:1). Pair it with `--color-on-accent`, which is its contrast text colour, and never use `--color-on-accent` on a background that is not the accent.

An accent-coloured **ink** is a different token. Use `--color-text-accent` and `--color-icon-accent` for accent-coloured text and glyphs: they resolve to a lilac ink (`#5c3878` in light mode, 8.4:1 on the page). The export's own binding for those roles is a light adornment that is only 1.4:1 as ink on the light page, so the library rebinds them.

```css
.promo-button {
  background-color: var(--color-accent);
  color: var(--color-on-accent);
}

.promo-link {
  color: var(--color-text-accent);
}
```

## Status colors

| Meaning | Fill              | Text on the fill    | Wash                       |
| ------- | ----------------- | ------------------- | -------------------------- |
| Success | `--color-success` | `--color-on-success` | `--color-success-muted`   |
| Error   | `--color-error`   | `--color-on-error`   | `--color-error-muted`     |
| Warning | `--color-warning` | `--color-on-warning` | `--color-warning-muted`   |

Status tokens are fills, and the `-muted` tokens are 25 % washes for tinted backgrounds. In light mode the warning fill is a pale yellow (`#ffdd89`) with a dark brown ink; do not use it as text. Use the status colours only for their meaning, and pair them with an icon or text: colour alone is never the signal.

Tecton also has an **info** ladder that the semantic set lacks, as `--tecton-color-info`, `--tecton-color-info-muted`, `--tecton-color-info-filled` and `--tecton-color-on-info`, and neutral status roles (`--tecton-color-status-neutral-*`). `--tecton-color-info-bright` is a highlight step (2.2:1 in light mode): use `--tecton-color-info` for text. `--color-background-error-inverted` is the error surface for inverted components such as toasts.

### Hues

For tinted badges and tokens, there are 40 hue tokens: `--color-background-<hue>` (a translucent tint), `--color-border-<hue>`, `--color-icon-<hue>` and `--color-text-<hue>` (an ink that meets 4.5:1) for blue, cyan, teal, gray, green, orange, pink, purple, red and yellow. `--tecton-color-text-lime` and the lime badge variant come from Tecton's own roles.

## Focus and selection

The focus ring is one colour everywhere, hot pink (`--focus-outline-color`: `#ff00aa` in light mode, `#ff52a8` in dark), including on destructive buttons, because Tecton defines a single focus colour. Selection is different on purpose: `--shadow-inset-selected` is a violet ring, never pink, so it cannot be mistaken for focus. See [Elevation](../elevation/) and [Accessibility](../accessibility/).

## Inverted surfaces and media

A dark region on a light page (or the reverse), and content over an image, need a pair of colours pinned to one side. Set `data-media-theme="dark"` or `data-media-theme="light"` (the `tct-media-theme` element does the same, can decide the side by measuring the painted surface, and also moves the focus ring): text, secondary text, surface, border, icon and accent colours are pinned. Whole scheme islands use `data-theme`. See [Theming](../theme/#nesting-themes).

## Data visualisation and syntax

Chart series use the data tokens: `--color-data-categorical-<hue>` for categories, and the five-step ramps `--color-data-<hue>-1` to `-5` for sequential values. They are **provisional**: Tecton documents no data-visualisation colours, so the mapping is a proposal built from Tecton accent hues and status roles (the teal, brown and indigo slots borrow lime, yellow and orchid). They may change.

Code highlighting uses 14 `--color-syntax-*` tokens (keyword, string, comment, number, function, type, variable, operator, constant, tag, attribute, property, punctuation and background), set by `tct-syntax-theme` and used by `tct-code-block` (both _planned_).

## Usage

Reference colours through CSS custom properties. In a component's attributes, use the named colour options the element documents:

```css
.summary {
  background-color: var(--color-background-surface);
  color: var(--color-text-primary);
  border: var(--border-width) solid var(--color-border);
}

.summary a {
  color: var(--color-text-accent);
}
```

Elements that accept a colour use tokens, not literals, so a `color="accent"` icon follows `--color-icon-accent` and adapts to a theme. Tecton's own tokens are also available as `--tecton-color-*` roles (452 of them) for cases the semantic names do not cover, and the opt-in `palette.css` provides the raw 1,820-colour palette as `--tecton-palette-<hue>-<surface>-<stop>`. The palette is for your own CSS: elements never reference it.

## Best practices

**Do:**

- Use semantic tokens (`--color-text-primary`) instead of raw hex values.
- Rely on the surface hierarchy (body, surface, card, popover) for layering, and on a one-pixel border for separation.
- Use status colours (success, error, warning) only for their semantic meaning, and pair them with an icon or text.
- Use the accent fill for the single most important action, and the accent ink tokens for accent-coloured text and icons.

**Don't:**

- Hardcode hex values, since they will not adapt to dark mode, to a theme, or to forced-colours mode.
- Mix accent colours with status colours in the same context.
- Use `--color-on-accent` on non-accent backgrounds.
- Use `--color-accent` as text or an icon colour: it is a fill, and it measures only 2.2:1 as ink on the dark page.
- Use `--color-text-disabled` for content.
- Register token properties as `<color>`; they hold `light-dark()` expressions that must stay live for nested schemes.
