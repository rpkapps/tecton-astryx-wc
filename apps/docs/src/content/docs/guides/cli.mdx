## Overview

`tct` is the primary interface for working with the design system, for people and for machines: element documentation, tokens, docs topics, agent-context generation and an MCP server, all through terminal commands, a typed JSON API or programmatic imports. It lives in the private `@tecton-wc/cli` package and reads one generated agent registry (the Custom Elements Manifest, the docs frontmatter with `keywords`, `dense` and `related`, the examples, the tokens and the docs topics). The docs site and the MCP route read the same registry, so the three surfaces cannot disagree.

```bash
tct --help
tct search dialog
tct component tct-dialog
tct docs tokens
```

Add an npm script alias (`"tct": "tct"`) so that scripts and agents use one stable command, and see [Working with AI](../working-with-ai/#the-tct-pattern) for why.

## Commands

| Command                      | What it does                                                                                                                                                  |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `component [tag]`            | With no argument, lists elements. With a tag, prints its documentation. Views for the attributes and properties, the examples and the source                    |
| `docs [topic] [section]`     | With no argument, lists the docs topics (every page in these guides). With a topic, prints it; with a section, prints just that section                       |
| `search <query>`             | Searches elements, controllers and docs in one ranked list, tagged with the follow-up command to run                                                          |
| `discover`                   | Finds elements and packages that other installed packages contribute                                                                                          |
| `controllers [name]`         | Lists the runtime controllers and utilities (the equivalent of upstream's `hook` command) or prints one                                                        |
| `doctor`                     | Diagnoses a project's setup: packages, stylesheet, registered elements and the freshness of the agent docs                                                    |
| `gap-report`                 | Routes a design-system gap (a missing element, attribute, token or icon) to the package that owns it                                                          |
| `layout`                     | Generates and checks layouts from a compressed expression: `layout grammar` prints the grammar, `layout check` validates an expression, `layout expand` produces `tct-*` markup |
| `init --features agents`     | Generates agent context: `--agent claude`, `--agent cursor` or `--agent codex`, and `--agent-docs-path <file>` for a custom location                            |
| `upgrade`                    | Detects a stale generated agent-docs block. `upgrade --apply` refreshes it without touching your own edits                                                    |
| `mcp`                        | Starts the MCP server over stdio, exposing `search(query)` and `get(name)`                                                                                    |

Search results are ranked by relevance, with name and keyword matches outranking incidental mentions in prose, and they can be restricted to one domain. A search result looks like this:

```text
$ tct search button

Results for "button":

  [element]  tct-button
             Triggers an action when activated. Use it for form submission, confirmation…
             → tct component tct-button

  [element]  tct-icon-button
             A button that shows only an icon…
             → tct component tct-icon-button
```

### Not in the first release

Upstream commands outside agent support are tracked as a follow-up and are not part of WP-AI: `theme` (building and exporting themes), `build`, `swizzle`, `integration` and `blog`. The templates library is deferred, so `template` and the template steps of the agent workflow are too. See [CLI Integrations](../cli-integrations/).

## Global options

These flags work with every command:

| Flag      | Effect                                                                                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `--dense` | Compressed, token-efficient output for AI context windows. Built from each element's authored dense doc, and complete with respect to its public API                       |
| `--json`  | Output as a stable, typed JSON envelope                                                                                                                                  |

Upstream also has `--detail <brief|compact|full>` for list views and a language switch; whether they are ported is decided in WP-AI and will show in the generated reference.

## JSON output

Every command supports `--json`. Responses are typed envelopes, modelled on upstream's:

```json
{"apiVersion": 1, "type": "component.detail", "data": {"name": "tct-button"}}
```

Errors carry a stable machine-readable `code`:

```json
{
  "apiVersion": 1,
  "error": "No element named \"tct-buttn\"",
  "code": "ERR_UNKNOWN_COMPONENT",
  "suggestions": [{"name": "tct-button", "reason": "similar name"}]
}
```

The `code` is a stable identifier. Branch on it, never on the human-readable `error` string, which changes freely as the wording improves. Every error envelope has a `code` (falling back to a generic one when no specific code applies). Codes are append-only: once shipped, a code's meaning never changes and it is never removed. New error conditions get new codes.

The CLI package exports a small module for consuming responses in TypeScript:

```ts
import {parseResponse, isError, assertResponse} from '@tecton-wc/cli/json';

const result = parseResponse(raw);
if (isError(result)) {
  switch (result.code) {
    case 'ERR_UNKNOWN_COMPONENT':
      // suggest the closest match from result.suggestions
      break;
    default:
      console.error(result.error);
  }
}
```

The error codes shown here (`ERR_UNKNOWN_COMPONENT`) are upstream's names and illustrate the pattern. The tct table is published in the generated reference.

## Exit codes

A command exits with `0` on success and non-zero on failure, and every non-zero exit that a command chooses is paired with a stable error code in `--json` mode. The contract tests check exit codes, the JSON contract, the dense projection, `init` behaviour, the protection of files you have edited during `upgrade`, and MCP search and get.

## Programmatic use

The same logic that powers the commands is meant to be importable as type-safe functions, so build tools and agents can call it without spawning a process. The shape of that module follows upstream (`component`, `docs`, `search` and so on, each returning the same data as the `--json` form); its final export names are defined by WP-AI.
