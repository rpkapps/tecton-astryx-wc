## Overview

Elevation tokens create depth through `box-shadow`. Three levels (low, med, high) establish a visual hierarchy for floating surfaces, and inset shadows provide hover, selection and status rings for interactive elements.

Tecton is flat. Its panels are separated by a one-pixel rule and by getting _darker_ in dark mode, and only a floating action button has a shadow in the design. The shadow tokens are therefore soft, single-layer black-alpha drops, kept so that elements that expose an `elevation` attribute still render sensibly. Menus, popovers and panels follow Tecton's own treatment instead: a one-pixel border and a recessed surface, with no drop shadow. Each element's page says what it draws.

## Elevation scale

Each level adds a stronger offset and blur. The shadow colour is black at a higher opacity in dark mode, so shadows stay visible against dark surfaces.

| Token                 | Light                          | Dark                           |
| --------------------- | ------------------------------ | ------------------------------ |
| `--shadow-low`        | `0px 1px 2px #0000001a`        | `0px 1px 2px #00000066`        |
| `--shadow-med`        | `0px 2px 6px #00000026`        | `0px 2px 6px #00000080`        |
| `--shadow-high`       | `0px 8px 24px #00000033`       | `0px 8px 24px #00000099`       |

Inset rings for state (each is a two-pixel inset shadow):

| Token                       | Meaning                                                                                       |
| --------------------------- | --------------------------------------------------------------------------------------------- |
| `--shadow-inset-hover`      | A mauve wash for hovered rows and items                                                       |
| `--shadow-inset-selected`   | A violet ring at 50 %. Selection is deliberately never the hot pink that means focus          |
| `--shadow-inset-success`    | A green ring at 30 %                                                                          |
| `--shadow-inset-warning`    | A yellow ring at 30 %                                                                         |
| `--shadow-inset-error`      | A red ring at 30 %                                                                            |

The complete values are on the [All tokens](../tokens/#shadow-tokens) page. Because Tecton has only one shadow in its design, a floating action button reads flatter here than an Astryx one does.

## Choosing a level

Pick the level by how far the surface sits from the page, not by how much shadow you want. Elevation encodes stacking order: a higher level means the surface is layered over more of the UI. Use exactly one level per surface, and only raise a surface above `none` when it actually sits above other content.

| Level  | When to use                                                                                                                                                                                                  | Examples                                                        |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------- |
| `none` | The element is flat and embedded in the surface; it is part of the page, not layered above it. The default for every surface except the chat composer.                                                     | A card in a grid, an inline banner, a standard button           |
| `low`  | The element is in the normal page flow but should read as distinct from the background. Use for emphasis or to separate it from the surface behind it; it still sits on the page, not floating over content. | A raised card that needs emphasis, the chat composer            |
| `med`  | The element sits over other content on the same page; it floats above nearby elements but not the whole screen.                                                                                              | A popover, a floating banner, a floating action button          |
| `high` | The element is placed over the entire UI; it is the topmost layer and typically has a backdrop or takes focus from everything else.                                                                          | A modal dialog, a full-screen overlay surface                   |

If two surfaces overlap, the one on top takes the higher level. If a surface does not overlap anything, it is `none` or `low`; never `med` or `high`.

## The elevation attribute

Configurable surfaces expose a single `elevation` attribute instead of asking you to hand-write a `box-shadow`. It takes the graded enumeration `none`, `low`, `med` or `high`, narrowed per element to the steps that surface needs: `tct-card`, `tct-clickable-card`, `tct-selectable-card`, `tct-button`, `tct-icon-button`, `tct-button-group` and `tct-banner` expose the full scale, while `tct-chat-composer` exposes only `none` and `low`. `none` is a flat literal (`box-shadow: none`); the other levels map to the `--shadow-*` tokens above, so a surface stays theme-agnostic.

Defaults preserve the current appearance: every surface defaults to `none` except the chat composer, which defaults to `low`. Set `elevation="none"` to flatten it; the flat composer draws a border with the same rest, hover and focus treatment as a text input.

```html
<!-- Flat by default; raise only when the surface needs to float. -->
<tct-card elevation="low">Raised card</tct-card>

<!-- A floating action button. -->
<tct-icon-button label="New" variant="primary" elevation="med">
  <tct-icon slot="icon" name="add"></tct-icon>
</tct-icon-button>

<!-- Flatten the composer (it defaults to low). -->
<tct-chat-composer elevation="none"></tct-chat-composer>
```

The exception is surfaces that always float and have no attribute: dialogs, popovers, tooltips, toasts, hover cards, dropdown menus and the elements that compose them bake their treatment in and never expose the attribute. Flow content (inputs, text, layout) is never elevated; fields use inset rings, which are a separate concept from elevation.

## Usage

When building a custom surface, read elevation from the token scale rather than a hand-rolled shadow, which is the same token an element's `elevation` attribute resolves to:

```css
.dropdown {
  box-shadow: var(--shadow-med);
}

.dialog-like {
  box-shadow: var(--shadow-high);
}

.input-selected {
  box-shadow: var(--shadow-inset-selected);
}
```

Depth in Tecton is also drawn without shadows. Use a border (`var(--border-width) solid var(--color-border)`) and the surface hierarchy (see [Color](../color/)) to separate a panel from the page, as Tecton's own panels do.

## Best practices

**Do:**

- Reach for the `elevation` attribute on a configurable surface before writing any custom shadow.
- Choose the level by how far the surface sits from the page: `none` when flat or embedded, `low` when in flow but distinct, `med` when over page content, `high` when over the whole UI.
- Use inset shadows for input hover, selection and status states; they compose better than outlines, and selection never uses the focus pink.
- Separate flat panels with a border and the surface hierarchy.

**Don't:**

- Hand-write a `box-shadow` in app code; set the attribute or read the token instead.
- Raise a surface that does not sit above other content; a non-overlapping surface is `none` or `low`, never `med` or `high`.
- Stack multiple elevation levels on the same element.
- Use elevation shadows for decorative borders. Use `--color-border` instead.
