## Overview

The radius scale uses a semantic naming system: inner, element, container, page. Each level fits a specific context. `--radius-none` and `--radius-full` are fixed anchors. Radii are Tecton's, and Tecton's corners are uniformly tighter than Astryx's.

## Radius scale

| Token                | Tecton  | Astryx  | Role                                                                                              |
| -------------------- | ------- | ------- | ------------------------------------------------------------------------------------------------- |
| `--radius-none`      | 0 px    | 0 px    | Flush seams                                                                                       |
| `--radius-inner`     | 2 px    | 4 px    | Dense controls: checkbox box, menu items, option rows, keyboard keys                              |
| `--radius-element`   | 4 px    | 8 px    | Buttons, icon buttons, toggles, fields, code blocks, banner cards, menu panels, segmented controls |
| `--radius-container` | 8 px    | 12 px   | Cards, sections, dialogs, popovers                                                                |
| `--radius-chat`      | 12 px   | 28 px   | Chat bubbles and composer                                                                         |
| `--radius-page`      | 16 px   | 28 px   | Page-level surfaces                                                                               |
| `--radius-full`      | 9999 px | 9999 px | Pills and circles                                                                                 |

`--radius-element` (4 px) is Tecton's default corner. Two names do not match their meaning: `--radius-chat` carries Tecton's 12 px step, and `--radius-page` its 16 px step, because they keep the Astryx names for token compatibility. Astryx lets a theme scale the whole set with a multiplier; here, override the tokens themselves. The Tecton export's own scale is also available (`--tecton-radius-0`, `-25`, `-50`, `-100`, `-150`, `-200` and `-round`).

The [All tokens](../tokens/#radius-tokens) page has the values and their status.

## Concentric radius

When a rounded container has padding, inner elements need a smaller radius to appear concentric. Elements such as `tct-card` handle this automatically: the inner radius is computed as `max(0, outerRadius - padding)`. Do the same in your own nested surfaces:

```css
.panel {
  --panel-padding: var(--spacing-2);
  padding: var(--panel-padding);
  border-radius: var(--radius-container);
}

.panel > .swatch {
  /* concentric: the outer radius minus the padding, never negative */
  border-radius: max(0px, calc(var(--radius-container) - var(--panel-padding)));
}
```

## Special cases

Some Tecton shapes are not a single role radius. They are handled inside the elements and are worth knowing when you style over them:

- **Buttons and toggle buttons never take a `border-radius` shorthand.** Inside a button group the elements square their interior corners one corner at a time, and the group wrapper itself has no radius. A shorthand on the button part flattens every corner. Use the logical per-corner properties (`border-start-start-radius` and its siblings) if you must override.
- **Banner cards** are 4 px, and only for the card container; section banners are full-bleed and square.
- **Dropdown menus** are 4 px only in popover presentation; the bottom-sheet presentation stays square against the viewport edge. **Popover** keeps 8 px, because it underlies mega menus and sheets that square themselves.
- Menu items and selector option rows are 2 px, inset inside the panel.
- **Tokens (chips) and badges** are full pills, so single digits render as circles.
- Checkboxes are 2 px; radios, switches and avatar circles use full.

Tecton design details that are not expressed: a pill-shaped floating action button (it is a button with an elevation, so 4 px), square-cornered list rows (they inherit 4 and 2 px), and a circular versus rounded-square icon button (there is no shape attribute).

## Best practices

**Do:**

- Use `--radius-element` for interactive controls (buttons, inputs, selectors).
- Use `--radius-container` for content containers (cards, panels, dialogs).
- Use `--radius-full` for pill shapes (badges, tags, status dots).
- Use `--radius-inner` for dense items inside a container.

**Don't:**

- Use `--radius-page` or `--radius-chat` for small elements; they are meant for page-level and chat surfaces.
- Hardcode radius values; they will not follow a token override.
- Set a `border-radius` shorthand on a button part inside a button group.
