## Overview

The design system uses a 4 px base-unit spacing scale. Element `gap` and `padding` attributes accept step values that map to these tokens. The scale gives fine-grained control at the small end (2, 4 and 6 px) and a consistent rhythm at larger sizes (multiples of 4 px).

Tecton's own spacing scale is the same 4 px grid. Its `space.25` (2 px) and `space.75` (6 px) are `--spacing-0-5` and `--spacing-1-5` here, and Tecton adds larger steps (56 to 144 px) that no element uses. So spacing is **the original scale, kept**: the tokens are labelled _default_, not Tecton, and no spacing exceptions have been approved.

## Scale

| Step | Token              | Value |
| ---- | ------------------ | ----- |
| 0    | `--spacing-0`      | 0 px  |
| 0.5  | `--spacing-0-5`    | 2 px  |
| 1    | `--spacing-1`      | 4 px  |
| 1.5  | `--spacing-1-5`    | 6 px  |
| 2    | `--spacing-2`      | 8 px  |
| 3    | `--spacing-3`      | 12 px |
| 4    | `--spacing-4`      | 16 px |
| 5    | `--spacing-5`      | 20 px |
| 6    | `--spacing-6`      | 24 px |
| 7    | `--spacing-7`      | 28 px |
| 8    | `--spacing-8`      | 32 px |

The same values are available under the Tecton export's own names as `--tecton-space-*` (see [All tokens](../tokens/#tecton-export-scales)).

## Usage

Most elements take a `gap` attribute using step values. For custom layouts, use the spacing tokens directly in CSS:

```html title="Spacing through element attributes (preferred)"
<!-- gap 4 is 16 px -->
<tct-vstack gap="4">
  <tct-text>First</tct-text>
  <tct-text>Second</tct-text>
</tct-vstack>
```

```css title="Spacing through tokens (custom layouts)"
.custom-layout {
  padding: var(--spacing-4);
  gap: var(--spacing-3);
}
```

Use logical properties for padding and margin (`padding-inline`, `margin-block-start`) so that layouts mirror correctly in right-to-left.

## Adopting Tecton spacing

The plan for spacing is deliberately conservative, because a spacing change moves every layout. The library keeps the original structural baseline, and would apply a Tecton value only where it has been checked against real content, all required states, long and localised labels, narrow containers, zoom and font loading, with no new clipping, overlap, inaccessible overflow or unusable interaction.

Tecton's design measures some geometry that differs from the values the elements use (list rows of 44 and 36 px, table rows of about 44 and 34 px, a smaller switch, chip heights of 24, 20 and 18 px, and others). None of it is applied yet. It is a candidate list for a spacing-exceptions review, and any accepted exception will be recorded with the original value, the attempted Tecton value, the retained value and the reason, and will use a named token rather than a one-off literal.

## Best practices

**Do:**

- Use element `gap` attributes when available; they handle spacing compensation.
- Stay on the scale for consistency. If a value is not on the scale, reconsider the design.
- Use smaller steps (0.5 to 2) for tight internal spacing and larger steps (4 to 8) for section gaps.
- Keep touch targets at least 24 by 24 px; the spacing of adjacent targets counts toward that.

**Don't:**

- Use arbitrary pixel values outside the scale.
- Mix spacing tokens with raw `px` or `rem` values in the same element.
