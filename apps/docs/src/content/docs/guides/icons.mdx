Icons are data, not components. `tct-icon` renders an `IconDefinition` (a viewBox and a list of SVG paths) that it finds by name in a registry. Sets are ES modules of icon data that you import or register, so a page pays only for the glyphs it uses.

<Example
  title="Icons by name"
  description="A role icon, and a Tecton domain icon in its outlined and filled forms."
  source={`<tct-hstack gap="3" v-align="center">
  <tct-icon name="close" size="lg"></tct-icon>
  <tct-icon name="well" size="lg"></tct-icon>
  <tct-icon name="well-filled" size="lg"></tct-icon>
</tct-hstack>`}
/>

The icon data (`@tecton-wc/icons`), the registry (`@tecton-wc/core/icons/registry.js`) and the `tct-icon` element all exist. Elements that show an icon (buttons, banners, fields) take a registered name through their `icon` attribute or a `tct-icon` in their `icon` slot.

## Where the icons come from

| Set                       | What it is                                                                                                                       | Licence                                                    |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| Default set               | Semantic role names (`close`, `chevronDown`, ...) mapped to [Lucide](https://lucide.dev) glyphs. Registered for you              | Lucide is ISC; the glyphs it derived from Feather are MIT  |
| Tecton domain icons       | 18 oil-and-gas and subsurface glyphs, each with an outlined and a filled variant. Registered for you                              | Supplied by the owner as part of Tecton                    |
| Full Lucide set           | About 1,850 glyphs, opt-in, under a `lucide:` namespace                                                                          | ISC and MIT, as above                                      |

The default set is registered at the lowest priority the first time a `tct-icon` connects, and it has no import-time side effects. Anything you register overrides it. Note that Tecton's larger 131-glyph design set is not used: its licence and provenance are not recorded, so the Tecton-specific glyphs are the 18 domain icons and everything else is Lucide.

Lucide icons are stroke icons: `mode: 'stroke'` on a 24 by 24 viewBox with a stroke width of 2, which you can change with the `--icon-stroke-width` custom property. Tecton's own glyphs are filled shapes drawn on a 16 px grid (their viewBox is cropped to the artwork, for example `1 1 14 14`).

`numberInput:stepperDown` is a namespaced glyph owned by the number input, which is _planned_ (see below). Directional glyphs mirror in right-to-left contexts by CSS, with one fixed glyph flipped from the ambient direction, so there is no per-direction name swap and no flash on the server.

The Tecton design has no glyph for six of these roles (`chevronsLeft`, `chevronsRight`, `calendar`, `clock`, `checkDouble` and `stop`), which Lucide covers. Tecton's design also draws `moreHorizontal` as vertical dots; the default here is Lucide's horizontal ellipsis. Both are open design questions, so the Lucide glyphs stay for now.

### Tecton domain icons

Eighteen glyphs for subsurface work, each as `<name>` (outlined) and `<name>-filled`:

`christmas-tree`, `drill-bit`, `fault`, `geobodies`, `geostructure`, `horizon`, `log-curve`, `oil-rig-offshore`, `rock-formations`, `seismic`, `strata`, `surface`, `trajectory`, `valve`, `velocity-model`, `well`, `well-pick` and `well-plan`.

`strata` is a coloured glyph: it carries its own colours instead of inheriting the text colour, and it is re-expressed as a fan of wedges, which is a bounded approximation of the original gradient. The other 17 render pixel-identically to their original markup.

## Using icons

<Example
  title="Decorative and meaningful icons"
  description="The first icon is decorative and hidden from assistive technology. The second has a label, so it is an image with an accessible name."
  source={`<tct-hstack gap="3" v-align="center">
  <!-- decorative: hidden from assistive technology (the default) -->
  <tct-icon name="search"></tct-icon>

  <!-- meaningful: a label gives it role="img" and an accessible name -->
  <tct-icon name="warning" label="Warning" color="warning"></tct-icon>
</tct-hstack>`}
/>

Icons inherit the surrounding text colour. Elements that take an icon (buttons, banners, fields) accept a registered name in their `icon` attribute, a `tct-icon` in an `icon` slot, or a plain inline `<svg>`. Colour options such as `color="accent"` point at the icon colour tokens (`--color-icon-accent` for accent, because the accent fill itself is too low in contrast to be an icon colour).

The `size` attribute takes `xsm`, `sm`, `md` and `lg`: 12, 16, 20 and 24 px, the same values as Tecton's icon sizes (`--tecton-icon-size-50` to `-200`). Without one, an icon takes the size that the element around it supplies (a button sets it from the button size), and otherwise `md`.

## Custom icons

For icons that are not in the set, register data, slot an SVG, or import a module.

```js title="Register an icon by name"
import {registerIcons} from '@tecton-wc/core/icons/registry.js';

registerIcons({
  logo: {
    viewBox: '0 0 24 24',
    mode: 'fill',
    paths: [{d: 'M12 2 2 22h20L12 2Z'}],
  },
});
```

```html
<tct-icon name="logo" label="Acme"></tct-icon>
```

A slotted SVG needs no registration. It goes in the default slot and is used as is; the slot is also the fallback shown when `name` is not registered:

<Example
  title="A slotted SVG"
  description="Your own svg in the default slot is sized and coloured like a registry glyph."
  source={`<tct-icon size="lg" color="accent" label="Warning triangle">
  <svg viewBox="0 0 24 24" fill="currentColor"><path d="M12 2 1 21h22L12 2Zm1 15h-2v-2h2v2Zm0-4h-2V9h2v4Z" /></svg>
</tct-icon>`}
/>

An `IconDefinition` has a `viewBox`, a list of `paths` (each a `d` and an optional `fillRule`), a `mode` of `fill` or `stroke`, an optional `strokeWidth`, `mirrorInRtl` for directional glyphs, and `colored` for glyphs that carry their own colours. A glyph that a list of paths cannot express (per-shape colours) can supply an `svg` body instead, which is passed through the HTML sanitiser once when it is registered and cloned for each use, never trusted as-is.

Registered names can also be lazy loaders, `() => import('./my-icon.js')`, so a large set costs nothing until an icon is used:

```js
import {registerIcons} from '@tecton-wc/core/icons/registry.js';

registerIcons({logo: () => import('./icons/logo.js').then((m) => m.default)});
```

## Overriding the defaults

Icons are looked up by name through two layers. The default set lives in the lower layer, and anything you register goes in the upper layer, so registering a name replaces the default for that name only. To swap one role's glyph, register the same name:

```js
import {registerIcons} from '@tecton-wc/core/icons/registry.js';
import xMark from './my-icons/x-mark.js';

registerIcons({close: xMark}); // every close button now uses your glyph
```

To swap the whole set, register the roles you want (`registerIcons`, or a per-icon import from another set); `resetIcons()` clears both layers. Subscribers (rendered icons) refresh when the registry changes, so registration order relative to rendering does not matter.

A theme can carry its own icons: `defineTheme` takes an `icons` map (name to definition or lazy loader, as `registerIcons` takes), and `extends` merges a child's icons over its base's. Applying a defined theme's icons is left to your code for now (`registerIcons(theme.icons)`), because `tct-theme` does not apply a defined theme yet.

## Tree-shaking and Lucide

Every glyph is a module, so you import only what you use:

```js
import well, {filled as wellFilled} from '@tecton-wc/icons/tecton/well.js';
import activity from '@tecton-wc/icons/lucide/activity.js';
import {registerIcons} from '@tecton-wc/core/icons/registry.js';

registerIcons({well, 'well-filled': wellFilled, activity});
```

To register the whole Lucide set under a namespace, so it never shadows the role names, use the generated helper. It registers lazy loaders, so nothing is downloaded until an icon renders:

```js
import {lucideIcons} from '@tecton-wc/icons/lucide.js';
import {registerIcons} from '@tecton-wc/core/icons/registry.js';

registerIcons(lucideIcons, {namespace: 'lucide'});
```

```html
<tct-icon name="lucide:activity"></tct-icon>
```

Deprecated Lucide aliases (for example `more-horizontal`) resolve to the same module as the canonical name. The Tecton domain set is also available as `tectonIcons` (lazy loaders), `tectonIconNames` and `tectonIconMeta` (a label, a description and a `colored` flag per glyph) from `@tecton-wc/icons/tecton.js`.

## Component and library icons

A glyph that belongs to one component or library gets a namespaced key (`numberInput:stepperDown`, `richtext:bold`) instead of a new semantic name. It resolves through the same registry, and you override it in the same way, but the shared list of role names stays reserved for glyphs that the whole system uses, so adding a component glyph does not make every downstream registry grow a key.

```js
import {registerIcons} from '@tecton-wc/core/icons/registry.js';

// The number input renders `numberInput:stepperDown`; override it independently of `chevronDown`.
registerIcons({'numberInput:stepperDown': myCaretDown});
```

`registerIcons(icons, {namespace: 'richtext'})` prefixes every key for you (`richtext:bold`). Ship the fallback in the default set under the same key, so the glyph still renders with no configuration.

## Adding new icons

To add a new semantic icon name to the design system, only for a glyph that the whole system shares (a component-owned one takes a namespaced key instead):

1. Add the name and its glyph to the default set in `@tecton-wc/icons` (`src/default.ts`). Roles keep their semantic name and map to a Lucide glyph; mark directional roles `mirrorInRtl`.
2. Add a row to the Available names table on this page.
3. Regenerate (`pnpm generate`) and commit only the source. Generated per-icon modules are build output.

This is a change to a shared package, so contributors working in a component folder propose it through their work package's `requests` rather than editing the package.
