Design tokens are CSS custom properties, declared once on the document by `tokens.css`. Elements read them through the cascade, so a token set on any ancestor reaches every element below it. This page is the authored reference for the tokens that you will use in your own CSS. The [design tokens reference](/reference/tokens/) is the complete generated list (every token, with its light and dark values and its status), built from `@tecton-astryx/tokens/tokens.json`.

The token build emits 786 custom properties plus 1,820 opt-in palette colours. Each token has a status that says where its value comes from:

| Status           | Count | Meaning                                                                                                                                                |
| ---------------- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Tecton           | 515   | From the Tecton design-system export, which is authoritative for role values in both modes                                                              |
| Tecton (bound)   | 180   | A Tecton role bound to a semantic token, from the owner's Tecton theme bindings where the export has no role of that name                              |
| default          | 18    | A default value that Tecton deliberately keeps (the spacing scale, three tiny font sizes)                                                              |
| retained default | 10    | No Tecton value exists, so the original value is kept on purpose (motion)                                                                              |
| Provisional      | 63    | No Tecton decision yet. A proposal (56 data-visualisation colours, `--size-element-lg`, and a few extras)                                              |

Breakpoints and z-index are retained defaults too, but they are not custom properties; see [Values that are not tokens](#values-that-are-not-tokens).

## Naming

| Kind                   | Pattern                                             | Example                                    |
| ---------------------- | --------------------------------------------------- | ------------------------------------------ |
| Portable semantic      | The semantic name (`--color-*`, `--spacing-*`, `--radius-*` and so on) | `--color-text-secondary`, `--shadow-inset-error` |
| Tecton semantic role   | `--tecton-<category>-<role>[-<state>]`              | `--tecton-color-action-primary-bg-hover`   |
| Palette primitive (opt-in) | `--tecton-palette-<hue>-<surface>-<stop>`       | `--tecton-palette-mauve-on-light-680`      |
| Component public       | `--<component>-<property>[-<state>]`                | `--button-focus-offset`                    |
| Component private      | `--_<component>-<property>`, not an API             | `--_button-bg`                             |

The semantic names are stable and shared by every element. Tecton-only roles live under `--tecton-*`. Elements never reference palette variables.

### Hue, data and syntax tokens

- **Hue tokens (40).** `--color-background-<hue>`, `--color-border-<hue>`, `--color-icon-<hue>` and `--color-text-<hue>` for the hues blue, cyan, teal, gray, green, orange, pink, purple, red and yellow. Backgrounds are translucent tints, and the text roles are inks that meet 4.5:1.
- **Data-visualisation tokens (56, provisional).** `--color-data-categorical-<hue>` for blue, orange, purple, green, pink, cyan, red, teal, brown and indigo; `--color-data-neutral`; and five-step sequential ramps `--color-data-<hue>-1` to `-5` for blue, shamrock, orange, pink, purple, red, teal, yellow and gray. Tecton documents no data-visualisation colours, so this is a proposed mapping built from Tecton accent hues and status roles, using palette colours only. The teal, brown and indigo slots borrow lime, yellow and orchid.
- **Syntax tokens (14).** `--color-syntax-<role>` for keyword, string, comment, number, function, type, variable, operator, constant, tag, attribute, property, punctuation and background.
- **Tecton roles (452).** `--tecton-color-*`: explicit per-state action fills (`--tecton-color-action-primary-bg-hover`), input roles, status ladders (including the info and neutral ladders that the semantic set lacks), table and top-navigation surfaces, tabs, toggles, chips and more. These are the roles that elements bind for their Tecton behaviour; use them in your own CSS when a semantic name does not express what you need.

## Tecton export scales

The Tecton export defines scales that no semantic token maps to. They are available as tokens for your own CSS:

- `--tecton-space-0` to `--tecton-space-1800` (20 steps, 0 to 144 px; the numeric part is a design step, not pixels);
- `--tecton-radius-0`, `-25`, `-50`, `-100`, `-150`, `-200` and `--tecton-radius-round` (0, 2, 4, 8, 12, 16 and 1000 px);
- `--tecton-icon-size-50` to `-400` (12, 16, 20, 24, 32, 40 and 48 px).

## Usage

Use tokens through `var()` in any CSS, and reference names from JavaScript through the metadata module:

```css
.panel {
  padding: var(--spacing-4);
  border-radius: var(--radius-container);
  background-color: var(--color-background-surface);
  color: var(--color-text-primary);
  border: var(--border-width) solid var(--color-border);
  transition: opacity var(--duration-fast) var(--ease-standard);
}
```

```js
import {tokens, tokenVar, breakpoints} from '@tecton-astryx/tokens/tokens.js';

tokens['--radius-element'].light; // '4px'
tokenVar('--color-accent'); // 'var(--color-accent)'
breakpoints.values.lg; // 1024
```

The metadata module is a snapshot for docs and tools. Runtime styling always uses `tokens.css`.
